# #43881 — Step 2.3: Stop logging PAT/API key values in plaintext

Part of [Personal Access Tokens](43881-personal-access-tokens.md). Requires
[Step 2](43881-02-authentication-and-authorization.md) to be done first (needs `api_key_from_request`
to exist so this step knows the real param names to filter). Does not depend on Step 2.1 or 2.2.

**Why this step exists:** while investigating this repo's logging/PII posture, a real credential
leak was directly observed in this session's own dev server log, not hypothesized:
Parameters: {"project_id"=>"pat-test-project", "key"=>"redmine-pat-370d782c5610c7af2ee83b403f0250b11943e532"}

The full, valid Personal Access Token value appears in plaintext in the application log whenever
it's sent as the `?key=` query param. `config/application.rb` only filters `:password`
(`config.filter_parameters += [:password]`) — there's no `config.load_defaults` call in this app,
so Rails' broader built-in default filter list (`token`, `secret`, `_key`, `crypt`, `otp`, etc.)
was never merged in either; only the one explicit key is filtered. The legacy API key had this
exact same exposure already, but PAT was specifically designed as the more security-conscious
replacement (mandatory expiration, scoping, revocation) — shipping it with the same
plaintext-in-logs behavior undercuts that.
**Scope note, read before starting:** this step is the narrow, targeted fix — add the specific
credential-shaped param names to `config.filter_parameters`. It is deliberately NOT "add
structured logging" or "add lograge/semantic_logger" — those are a separate, bigger initiative
with their own gem and design tradeoffs, and this repo's own constraint (see the index doc) is no
new gems per step. Headers (`X-Redmine-API-Key`) are unaffected by this fix and don't need it —
`config.filter_parameters` only redacts the `Parameters:` log line built from query/POST params,
never arbitrary request headers, so header-based PAT/API-key auth was never exposed this way in
the first place. Only query-string/POST-body param names need filtering.
